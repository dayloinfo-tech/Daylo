Production Firestore Security Rules

Ready to deploy to Firebase Console > Firestore Database > Rules.

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // Helper function to check if the caller is an authenticated administrator
    function isAdmin() {
      return request.auth != null && (
        request.auth.token.email == "dayloinfo@gmail.com" ||
        get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role == "admin"
      );
    }

    // Users collection: user can read/write their own profile; admins have full access
    match /users/{userId} {
      allow read: if request.auth != null && (request.auth.uid == userId || isAdmin());
      allow create: if request.auth != null && request.auth.uid == userId;
      allow update: if request.auth != null && (request.auth.uid == userId || isAdmin());
      allow delete: if isAdmin();
    }

    // Tasks collection: user owns their tasks
    match /tasks/{taskId} {
      allow read, write: if request.auth != null && (
        resource == null || resource.data.uid == request.auth.uid || isAdmin()
      );
    }

    // Rescheduled slot telemetry / misses
    match /misses/{missId} {
      allow read, create: if request.auth != null;
      allow update, delete: if isAdmin();
    }

    // Contact messages
    match /contact_messages/{messageId} {
      allow create: if true;
      allow read, delete: if isAdmin();
    }

    // Application & n8n configuration
    match /app_config/{document=**} {
      allow read: if true;
      allow write: if isAdmin();
    }

    match /n8n_config/{document=**} {
      allow read: if request.auth != null;
      allow write: if isAdmin();
    }
  }
}

Daylo Platform Instructions & Architecture

1. Hardcoded Administrator Authentication

The administrator credentials (dayloinfo@gmail.com / Admin@2026) are registered into ADMIN_CONFIG. Authentication verifies matching email or Firestore document role: "admin".

2. AI Limit Enforcement

AI limits (Free: 60 mins, Pro: 300 mins, Premium: 999999 mins) are checked by checkAILimit() in app.js exclusively prior to sending prompts to Ashley AI assistant. Usage only tracks when users chat with the AI; all other features (tasks, calendar sync, auto-planning, energy insights) are completely free on all plans without limits.

3. n8n Integration

All AI scheduling calls send the user's Firebase token as Authorization: Bearer <token> to your n8n webhooks. Update the endpoints in Tab 2 or in N8N_WEBHOOKS to point to your self-hosted n8n instance.

Notification System

n8n should write directly to users/{uid}/notifications/{id}. The app listens to this collection in real-time.

4. Vercel Pure Static Deployment

All files are pure HTML, CSS, and Vanilla JavaScript with CDN dependencies. There is no build step or node runtime needed; drag and drop or push to GitHub and deploy straight to Vercel.
